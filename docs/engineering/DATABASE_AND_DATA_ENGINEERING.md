# Database and data engineering

## Storage

| Item | Location (`WIREFRAME_DATA_DIR`, default `<repo>/var`) | Written by |
|---|---|---|
| SQLite database | `wireframe.db` (+ `-wal`, `-shm`), or `WIREFRAME_DATABASE_URL` | `app/core/database.py` |
| Uploaded photos (GPS EXIF stripped) | `uploads/` | `app/services/analysis.py: ingest` |
| Wire masks, overlays | `renders/` | `save_wire_mask`, `app/services/render.py` |
| PDF reports | `reports/` | `app/services/report_pdf.py` (rebuilt on every request) |
| Pre-migration copies | `backups/` | `backup_before_migration` |

### Connection settings

`_sqlite_pragmas` runs on every pooled connection:

* `foreign_keys = ON`, verified at startup by `assert_foreign_keys`;
* `journal_mode = WAL`, so the API reads while the worker writes;
* `synchronous = NORMAL`;
* `busy_timeout = 5000`.

## Migrations (`app/core/database.py: migrate`)

Migrations are additive and in place, and they run at startup. There is no migration tool and no down-migration.

1. `add_missing_columns` adds every column the ORM declares but an existing table lacks, using SQL defaults from the
   ORM.
2. A table is rebuilt (`_rebuild`) with the current CHECK constraint in two cases:
   * `detections`, when it still lists legacy class names (renamed via `LEGACY_CLASS_NAMES`) or lacks
     `service_drop` / `not_assessed`;
   * `reviews`, when it lacks `flagged`.
3. Backfills:
   * `records.backfill` sets `record_kind` (operational / test) on older rows;
   * `review_flow.backfill_legacy` (S18) maps every pre-S18 `reviews` row into `admin_decisions` with
     `source = legacy_review`. The original rows are kept.
4. **A copy of the database goes to `backups/` before any of these changes** (`backup_before_migration`).

## Data rules

* **Machine observations are never edited.** `analyses`, `detections` and `metadata_json` are written once by the
  pipeline (D-38). Review and decisions live in `review_progress` and in the append-only `admin_decisions`. An
  amended decision supersedes the previous one, and the earlier decision stays in the history.
* **Deletion is soft.** Admin "Delete inspection" archives the analysis (`POST …/archive`, restorable). Contacts are
  deactivated, never deleted. Hard delete (`DELETE /api/analysis/{id}`) exists for administrators only.
* **Location.** `pole_locations` holds one current location per pole, with `source` `exif` or `manual`. When an
  administrator drops a pin, the old value is kept in the audit trail. How a device location was captured at
  upload is stored in the analysis `metadata_json["location_capture"]`. Barangays are validated against `app/data/barangays_cavite.json`
  (`app/services/barangay.py`).
* **Audit.** Every state change by staff is an `audit_events` row (`app/services/audit.py: record`).
* **Configurable data.** `app_settings` holds key/value settings: `risk_rubric`, `decision_options`,
  `active_weights` and others. They are versioned where they affect results.

## Backups (`scripts/backup.py`, D-13)

```
python -m scripts.backup create  --dest <dir> [--data <var dir>]
python -m scripts.backup verify  <backup dir>
python -m scripts.backup restore <backup dir> --to <new empty dir>
```

`create` takes:

* the database, through SQLite's online backup API (consistent while the server runs);
* every file under `uploads/`, `renders/` and `reports/`.

Every file is fsynced. The copy must pass `PRAGMA integrity_check` and `foreign_key_check`. A SHA-256 manifest is
written last, then the directory is renamed atomically. `restore` refuses a non-empty target and verifies the copy
before and after. No retention policy is applied. Local backups are kept in `~/WIREFRAME-backups/`.
